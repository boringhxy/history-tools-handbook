# history-tools-handbook 核心平台对比改版设计方案

日期：2026-10-19

## 已确定的方向

保留全局矩阵，新增五平台专题深比与三组案例工作流。目标是帮助文史研究者根据研究任务选择入口，理解具体操作、人工复核、成果输出及跨平台衔接。

本文件记录已确认的设计基线；网页实现与验证状态见 verification.md。现有仓库为单文件 HTML 手册，设计延续离线阅读与打印能力。

## 一、范围与页面组织

保留现有研究说明、生命周期、全局矩阵、平台档案、工具目录、标准、研究空白和来源模块。新增专题置于全局矩阵之后、平台档案之前。三组专题案例并入现有组合工作流模块，原有四组流程保留。

专题顺序：任务入口 → 五平台定位 → 任务能力矩阵 → 平台详细流程 → 三组案例链接 → 证据与来源。

五个平台为识典古籍、南京大学数智文献处理平台、DocuSky、吾与点、DEDU 对读。南大沿用现有条目及 https://lab.digitalilab.cn/ 入口，不另建一个未经确认的期刊平台。

DocuSky、DEDU 纳入核心平台档案；识典仍是一平台，在其档案中拆分阅读与整理两个入口。以现有23个平台为基线，核对无重复后核心平台数为25。115项基础目录不因提升核心层级而增减；核对DEDU是否已有目录记录，未收录时以目录外新增核心平台说明。同步检查首页计数、矩阵、档案计数、无脚本说明、来源和README，避免口径冲突。

## 二、五平台的比较重点

| 平台 | 重点任务 | 流程组织 |
|---|---|---|
| 识典古籍·阅读入口 | 古籍发现、辅助阅读、书影核对 | 检索筛选 → 阅读 → 图文核对 → 记录底本与出处 |
| 识典古籍·整理入口 | 从影像到校订文本 | OCR → 文字校对／对勘 → 标点与实体校订 → 审核与发布；权限按实际入口说明 |
| 南京大学数智文献处理平台 | 近代期刊材料发现与核验 | 确定资源范围 → 检索筛选 → 文章与原页定位 → 核对卷期页码 → 整理专题材料 |
| DocuSky | 个人语料建库及检索分析 | 文本与元数据准备 → 格式转换 → 建库 → 检索统计 → 分析与输出 |
| 吾与点 | 从材料到结构化数据 | 定义字段／关系 → 配置规则和示例 → 自动抽取 → 人工校订 → 数据管理与输出 |
| DEDU | 平行文本对应关系的编辑、组织与分享 | 准备文本与出处 → 设计对应结构 → 编辑对应内容 → 注释与复核 → 分享与备份 |

上表为内容组织框架。正式网页只将有证据支持的功能写为现有能力；具体导入导出格式、自动处理能力及权限必须逐项核对。

## 三、专题矩阵

矩阵行使用研究任务，列使用五个平台。识典单元格中分别注明阅读／整理入口，避免读者误以为公共阅读权限包含全部整理功能。

任务包括：资源发现、自有材料输入、OCR与校订、全文／字段检索、语义／跨语种检索、原页回溯、多文本对读、自定义抽取与标注、个人建库、统计与可视化、协作复核、导出与备份。

每项能力分开记录：

- 实现方式：平台内完成／需外部工具／非主要用途／待确认。
- 证据状态：官方说明／已实测／公开证据不足。
- 补充条件：适用入口、版本、账号权限、材料限制、来源与核实日期。

未找到说明不等于不支持。来源页面可访问不等于所有功能已实测。“强／部分”的全局矩阵保留其原有覆盖度含义，不将它转换成性能或准确率排名。

专题支持按研究任务筛选，选择2—3个平台并排阅读，并提供重置。无匹配时显示清空条件入口；同一平台不重复加入。窄屏按平台卡片呈现详细比较，完整矩阵保留横向滚动。

## 四、平台档案模板

统一使用：研究问题、材料与权限、操作步骤、人工检查点、输出成果、下一步衔接、限制、来源与核实日期。

每个流程步骤写清输入、操作、输出。自动识别、抽取或问答之后标明人工检查点。跨平台箭头写清传递的数据、转换要求、可能损失的出处或结构信息，以及连接是否经过实测。

对读专项需检查：图文／异本／跨语种对象、篇章／段落／句词粒度、对应关系建立方式、拆分合并、缺文处理、注释、导航联动、协作、结构化导出。不得将并排展示写成自动对齐或自动校勘。

南大专项需检查：刊物与年代覆盖、缺卷缺期说明、刊名—卷期—文章—页面层级、检索范围与筛选、关键词和语义检索差异、影像回溯、问答引文依据、输出条件。机构对平台整体能力的介绍不能直接证明期刊模块有全部同类功能。

## 五、三组案例工作流

### A. 古籍整理与版本比较

输入：有明确版本说明、允许使用的同书异本文本及小组书影。

流程：定位底本 → 图文核对／校订 → 准备对应文本 → 建立DEDU对读结构 → 标记差异并说明判断 → 复核与分享。

成果：校订样例、对应文本、异文记录、底本说明。识典承担的操作与DEDU承担的操作分开展示；数据交接没有验证时标为建议路径。

检查：繁简和异体字归一化不能掩盖版本差异；文本缺段、不等长、顺序差异应可解释。

### B. 近代期刊专题研究

输入：研究者定义的一个概念或事件、明确的刊物与时间范围。

流程：确认南大资源覆盖 → 设计检索词及异称 → 检索筛选 → 核对文章及原页 → 记录卷期页码 → 整理有权取得的文本和元数据 → 按实际导出条件进入DocuSky建库或其他分析工具。

成果：检索日志、文章清单、逐条出处、专题语料说明和可用分析样例。

检查：区分搜索未命中与资源未收录；保留重复转载判断；按实际语料规模解释频次，不将命中数量直接视为历史影响力。

### C. 人物与事件信息抽取

输入：一批来源明确且允许处理的短文本。

流程：定义人物、事件、时间、地点和原文出处字段 → 在吾与点配置规则与示例 → 小样本抽取 → 人工核对 → 修订规则 → 导出核验 → 在DocuSky等工具开展适用的检索分析。

成果：经复核的数据表、字段说明、抽取配置、修改记录、原文出处和分析示例。

检查：同名人物、别称、模糊日期、否定与推测表述，以及关系究竟为原文陈述还是研究推断。

案例统一显示材料、目标、步骤、人工介入、成果、平台交接条件和失败情况。实际操作前称“示范流程”；完成操作并保存证据后才称“实测案例”。

## 七、实施顺序与验收

1. 获取仓库当前版本和适用项目指引，确认文件结构、核心数据和目录记录。
2. 完成五平台证据表，先核实南大期刊场景、DEDU与DocuSky的操作和输出条件。
3. 补充核心档案及来源，加入专题内容和三组示范流程。
4. 实现任务筛选与并排比较，延续现有单文件结构，不新增运行时外部依赖。
5. 检查桌面、移动、离线、打印及键盘操作；复核已有筛选和档案展开功能。
6. 更新README、全部计数与资料口径，准备可审阅版本后再进入发布步骤。

验收标准：

- 五平台均有统一档案；识典两入口清晰，南大条目身份不变。
- 三组流程均明确输入、人工判断、成果与衔接限制。
- 每项具体功能有来源及核实口径；没有来源的断言改为待确认。
- 导出声明区分正文、元数据、注释、对应结构与配置，不笼统写“支持导出”。
- 全局矩阵、115项基础目录与原有四组流程保留；全站计数一致。
- 新专题可离线阅读；筛选、比较、打印和原有功能正常。
