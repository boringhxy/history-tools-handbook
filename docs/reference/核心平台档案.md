### Zotero

研究资料入口与可复现引文管理中枢

通用文本 · 近现代文献 · 网页 · 采集 · 建库 · 出版 · 桌面端＋浏览器连接器＋可选云同步 · 开源核心；托管同步含额度

<a id="body-zotero"></a>

#### 标准工作流

1. 从网页、目录或标识符采集书目
2. 复核作者、版本、日期与馆藏字段
3. 以集合、标签、关联和笔记组织证据
4. 在写作软件中插入引文并生成参考文献
5. 导出 RIS/BibTeX/CSL JSON 并备份附件

#### 主要能力

* 网页元数据采集
* PDF与笔记关联
* 引文样式
* 群组协作

#### 优势与局限

* **优势：**适合作为跨平台研究入口
* **优势：**引用链条清晰
* **优势：**生态成熟且可迁移
* **局限：**网页元数据可能错误
* **局限：**不是史料转录或全文分析平台
* **局限：**同步与版权策略需另行规划

#### 适用研究

适合任何需要建立可核查书目、阅读笔记和引证记录的文史哲项目。

#### 证据与复核要求

采集器生成的字段必须逐条抽查；版本、译者、卷期和永久标识符是高风险字段。

#### 平台衔接

可接收各平台的报告与导出文件，并为 Omeka S、TEI Publisher 或论文写作提供规范引文。

#### 官方来源

* [Zotero Quick Start Guide](https://www.zotero.org/support/quick_start_guide)

<a id="profile-tropy"></a>

### Tropy

档案照片的本地整理、描述与细读工作台

档案照片 · 手稿 · 采集 · 标注 · 建库 · 本地桌面端 · 开源；数据默认本地

<a id="body-tropy"></a>

#### 标准工作流

1. 导入档案照片并保留原图
2. 建立项目、列表和元数据模板
3. 对图像区域作选择、转写与注释
4. 用标签和搜索聚合材料
5. 导出 JSON-LD、CSV 或研究包并备份项目

#### 主要能力

* 批量图像管理
* 区域级笔记
* 元数据模板
* 本地检索

#### 优势与局限

* **优势：**贴合档案馆拍摄后的真实工作流
* **优势：**原图与研究笔记紧密关联
* **优势：**离线与隐私友好
* **局限：**不是 OCR 引擎
* **局限：**多人实时协作有限
* **局限：**长期保存仍需独立策略

#### 适用研究

适合以档案馆照片、手稿影像和田野采集图像为主要证据的项目。

#### 证据与复核要求

元数据模板应在批量录入前确定；文件重命名、迁移和备份需保持图像与项目关联。

#### 平台衔接

可把图像送往 Transkribus/eScriptorium 识别，再把转写结果与说明回收到研究库。

#### 官方来源

* [Tropy Documentation](https://docs.tropy.org/)

<a id="profile-transkribus"></a>

### Transkribus

历史手稿与印刷文献的 HTR/OCR 生产环境

手稿 · 档案照片 · 近现代文献 · 采集 · 识别 · 标注 · 云平台＋桌面/网页工具 · 客户端与部分组件开放；云识别按服务规则

<a id="body-transkribus"></a>

#### 标准工作流

1. 上传图像或 PDF 并建立集合
2. 执行版面分析与行区分割
3. 选用公共模型或准备真值
4. 训练/应用 HTR 或 OCR 模型
5. 逐页校订并形成质量样本
6. 导出 TXT、PDF、PAGE XML、ALTO 或 TEI

#### 主要能力

* 版面分析
* 手写文本识别
* 模型训练
* 协作转录与多格式导出

#### 优势与局限

* **优势：**覆盖从图像到结构化转录的完整链条
* **优势：**适合定制历史书写模型
* **优势：**协作和格式生态较强
* **局限：**云端额度与数据政策需评估
* **局限：**模型迁移受字体、时期和版式影响
* **局限：**高质量真值成本高

#### 适用研究

适合信札、账簿、审判记录、报刊和成规模档案的转录项目。

#### 证据与复核要求

字符错误率不能代替史料学判断；应保存训练集、模型版本、抽样误差和人工校订轨迹。

#### 平台衔接

转写可送往 OpenRefine 清洗、INCEpTION/CATMA 标注，影像可通过 IIIF/Mirador 展示。

#### 官方来源

* [Transkribus Help Center](https://help.transkribus.org/how-do-i-transcribe-my-documents)
* [Transkribus Export Guide](https://help.transkribus.org/downloading)

### OpenRefine

表格史料的可追溯清洗、规范化与对账工具

通用文本 · 近现代文献 · 清洗 · 建库 · 本地网页式桌面工具 · 开源

<a id="body-openrefine"></a>

#### 标准工作流

1. 导入 CSV/Excel/JSON 并创建项目
2. 用分面与过滤发现异常
3. 聚类合并异写、拆分或转换字段
4. 与外部权威库对账并保留匹配依据
5. 导出清洗数据和操作历史

#### 主要能力

* 分面检查
* 聚类纠错
* 批量变换
* 实体对账

#### 优势与局限

* **优势：**操作历史可回放
* **优势：**适合姓名地名与日期规范化
* **优势：**无需改写原始文件
* **局限：**自动聚类可能误合并
* **局限：**复杂关系建模能力有限
* **局限：**需要明确标准词表和空值规则

#### 适用研究

适合人物表、地名表、书目表、档案目录和跨库数据整合。

#### 证据与复核要求

应保留原始数据、操作 JSON 和合并前后对照；同名异人不可只按字符串处理。

#### 平台衔接

通常位于 OCR/采集之后、Heurist/QGIS/Gephi/Omeka S 之前。

#### 官方来源

* [OpenRefine Documentation](https://openrefine.org/docs.html)

### INCEpTION

面向研究团队的语义标注与机器学习辅助平台

通用文本 · 近现代文献 · 标注 · 分析 · 自部署网页平台 · 开源

<a id="body-inception"></a>

#### 标准工作流

1. 创建项目并导入语料
2. 设计层、标签集与约束
3. 分配标注员并形成独立标注
4. 计算一致性、裁决分歧
5. 使用推荐器辅助标注
6. 导出标注语料和项目数据

#### 主要能力

* 多层语义标注
* 推荐器
* 一致性与裁决
* 团队权限

#### 优势与局限

* **优势：**适合严格的人工标注研究
* **优势：**支持复杂标注层
* **优势：**可形成训练和评测数据
* **局限：**部署和方案设计门槛较高
* **局限：**机器建议可能造成确认偏差
* **局限：**历史语言模型需领域适配

#### 适用研究

适合实体、事件、论证、情感或语义关系等需要一致性控制的项目。

#### 平台衔接

可接收清洗后的转录文本，导出结果进入 Gephi、Heurist 或统计环境。

### Heurist

人文研究关系数据库与轻量发布环境

通用文本 · 近现代文献 · 地图 · 建库 · 分析 · 出版 · 托管实例或自部署 · 开源；托管条件依实例

<a id="body-heurist"></a>

#### 标准工作流

1. 把研究问题转成实体、关系与出处模型
2. 导入或手工录入记录
3. 使用受控词表、关系和证据字段
4. 以地图、时间线和网络视图探索
5. 发布查询界面或导出数据

#### 主要能力

* 关系建模
* 表单录入
* 地图与时间线
* 研究数据库发布

#### 优势与局限

* **优势：**兼顾建模、分析和展示
* **优势：**特别适合人物—地点—事件结构
* **优势：**不要求先编程
* **局限：**灵活性会放大模型设计错误
* **局限：**大型项目需要权限和数据治理
* **局限：**复杂统计仍需外部工具

适合人物志、事件史、考古、收藏史和多表关联项目。

#### 证据与复核要求

必须保存数据字典、实体边界、关系方向、出处粒度和版本规则。

#### 平台衔接

### QGIS

历史地理编码、地图配准与空间分析平台

地图 · 档案照片 · 近现代文献 · 清洗 · 分析 · 出版 · 本地桌面端＋可选服务器 · 开源

<a id="body-qgis"></a>

#### 标准工作流

1. 整理地名、坐标、时间与出处字段
2. 配准历史地图并记录控制点
3. 建立矢量/栅格图层与坐标系
4. 执行叠置、距离、密度或时空分析
5. 制作地图版式并导出数据/图件

#### 主要能力

* 地理配准
* 空间数据管理
* 空间分析
* 地图制图

#### 优势与局限

* **优势：**方法成熟、插件丰富
* **优势：**支持可复现地理处理
* **优势：**可与多种数据格式衔接
* **局限：**坐标系和地名消歧易形成隐蔽误差
* **局限：**边界与位置不确定性需表达
* **局限：**地图视觉不能替代史料论证

#### 适用研究

适合路线、行政区、历史城市、环境史与事件空间分布研究。

#### 证据与复核要求

保存控制点、坐标参考系、地理编码来源、时间有效期和不确定性字段。

#### 平台衔接

上游常接 OpenRefine/Recogito/CHGIS，下游可进入网页地图、论文图件或 Omeka S 展示。

#### 官方来源

### 吾与点智能数据平台

中文文史材料的表格化、知识库化与智能分析平台

古籍 · 近现代文献 · 通用文本 · 清洗 · 标注 · 建库 · 分析 · 在线平台 · 平台服务；支持多格式导出

<a id="body-wuyudian"></a>

#### 标准工作流

1. 研究问题与样例 → 定义字段名称、描述、类型以及原文出处字段 → 字段字典
2. 字段与人工样例 → 选择模型，配置规则、提示语和示例 → 可复用的抽取配置
3. 小批文本／图片 → 生成结果并逐行比对原文，修订规则 → 经复核数据与错误记录
4. 复核数据 → 按模块导出数据；配置单独导出并保存 → 数据文件、配置和修订说明

#### 主要能力

* 表格与数据集
* 实体关系处理
* 知识库/图谱
* 智能体与应用

#### 优势与局限

* **优势：**中文文史场景集中
* **优势：**从数据整理延伸到应用
* **优势：**导出格式较丰富
* **局限：**需要账号；模型、积分与存储条件随服务规则变化。旧版标注功能与新版智能数据平台分开描述。
* **局限：**用户手册说明数据库可导出Excel、CSV、JSON、JSONL；表格字段／规则／示例配置可另导出JSON。不要把数据库导出视为完整图谱、标注与全部项目的无损导出。

#### 适用研究

适合古籍、人物资料、地方文献和专题资料的结构化与知识化实验。

#### 证据与复核要求

逐条核对同名人物、别称、时间推算、关系方向和否定表述；出处字段须在任务设计时加入。 核实口径：官方资料整理，未登录实测；2026-10-19。

#### 平台衔接

建议路径：复核后的CSV／JSON → 清洗字段 → DocuXML转换 → DocuSky；节点边表也可另行准备给网络工具。字段和关系映射均需验证。

#### 官方来源

* [吾与点：现行用户手册](https://help.wuyudian.net/docs/user-guide.html)
* [吾与点：平台概述](https://help.wuyudian.net/docs/overview.html)

### 识典古籍

分为公开阅读与项目整理两条工作流的古籍平台

古籍 · 采集 · 识别 · 清洗 · 标注 · 出版 · 在线平台 · 开放阅读与项目服务并存

<a id="body-shidian"></a>

#### 标准工作流

3. 多份文本 → COMPARATIVUS比较复用线索 → 回到上下文核验相似段落
4. 核验后的标记和段落 → 导出并保存原文、词表和修改记录 → 后续人物、空间或关系分析

* COMPARATIVUS比较文本复用，官网说明可将所选段落送回账号内MARKUS文件；该路径未实测。

#### 优势与局限

* **优势：**把实体标注、段落抽取与文本复用线索联系起来。
* **优势：**适合作为人物和关系建库前的人工审核环节。
* **局限：**自动标记受词表覆盖和同名歧义影响，不能自动完成身份考证。
* **局限：**相似段落不等于直接引用，更不能单独证明传播方向或历史因果。
