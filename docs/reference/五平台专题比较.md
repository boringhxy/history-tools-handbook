### 五条流程：材料如何变成研究成果

<a id="focus-shidian"></a>

找古籍 · 读书影 · 做整理

### 识典古籍

从古籍资源发现进入阅读；具备整理权限时，再进入图像识别与校订生产。

#### 材料与权限

平台古籍正文与书影；整理入口使用有权处理的古籍图像。 阅读与整理是两个入口。阅读平台公开开放；整理任务、材料上传和发布按实际项目权限确认。

1. 输入：资源与检索词

   **在阅读入口按分类、时代与关键词检索**

   输出：候选书目与命中段落
2. 输入：候选段落

   **切换图文对照，核对底本和校订状态**

   输出：可回溯的原文摘录
3. 输入：有权整理的图像／粗校文本

   **在整理入口进行OCR、文字对勘、标点与实体校订**

   输出：待审核的整理文本
4. 输入：整理文本

   **人工审核后按项目权限发布；核实可带走的数据**

   输出：文本成果与出处说明

#### 人工检查点

区分粗校与精校；核对异体字、避讳字、缺损、标点及底本。年代筛选不可直接当作精确成书年代。

#### 成果与导出

阅读产生带版本说明的摘录；整理产生经校订的文本。批量全文、影像、实体和校订记录的导出格式均需按项目确认。

#### 下一步衔接 · 建议路径

建议路径：识典摘录／校订文本 → DEDU或DocuSky。先确认取用权限，再携带书名、版本、卷页和原文位置；未验证直连，转换可能丢失字图坐标与校订记录。

近代史料 · 期刊专题

### 南京大学数智文献处理平台

围绕近代史研究问题发现多语种文献；期刊研究重点是资源范围、文章定位和出处核验。

#### 材料与权限

机构介绍的近代红色资源含文件汇编、日记、年谱、文集、回忆录、报刊等，不能据此推定覆盖全部近代期刊。 沿用现有南大平台入口。本次公开页面未显示可读操作界面；账号准入、期刊列表和模块权限尚未实测。

1. 输入：研究问题与时间范围

   **先核实资源目录和可访问范围**

   输出：实际可检索的刊物／年份清单
2. 输入：关键词、异称与语种

   **依可用功能检索，记录检索式、筛选条件与日期**

   输出：候选文章与命中记录
3. 输入：候选文章

   **检查卷期、原页及影像；这些期刊模块功能尚待验证**

   输出：经人工核对的出处表
4. 输入：获准使用的材料

   **按实际输出条件保存，必要时手工登记元数据**

   输出：专题材料清单；全文取得条件另核

#### 人工检查点

区别资源未收录、OCR未识别和检索未命中；核对刊名异称、缺卷缺期、转载重复、日期与页码。语义纠错后的正文须回到影像核验。

#### 成果与导出

期刊研究目标成果：文章清单、检索日志、卷期页码及原页依据。平台是否提供这些字段和批量下载仍需核验。

#### 下一步衔接 · 建议路径

建议路径：有权取得的文章文本与元数据 → DocuSky；书目 → Zotero。未验证平台直接导出或直连，无法导出时可依法手工登记出处，不承诺取得全文。

<a id="focus-docusky"></a>

个人语料 · 建库与分析

### DocuSky

将自己选定的文本与元数据组织为个人研究库，再用适用工具进行检索、统计与时空观察。

#### 材料与权限

经整理的文本、元数据和标记；建库文件采用DocuXML。原始图片／PDF不应直接等同于可分析语料。 云端建库需要账号；存储、配额、公开分享及机构版本条件以现行服务规范为准。

1. 输入：文本与来源表

   **明确每篇文献的标识、标题、日期和出处**

   输出：一致的文献及元数据结构
2. 输入：整理后的数据

   **使用转换工具生成并检查DocuXML**

   输出：可上传的建库文件
3. 输入：DocuXML

   **上传建立文献集，检查检索与字段分类**

   输出：个人研究数据库
4. 输入：选定语料与标记

   **按工具条件开展词频、文本比较或GIS观察**

   输出：分析结果及筛选、字段与参数记录

#### 人工检查点

检查文献切分单位、字段映射、分词和标记。比较词频时记录语料规模、筛选范围与归一化方法。

#### 成果与导出

优先保存DocuXML源文件、字段字典和分析结果；各分析工具的输出格式不同，不承诺注释、关系和全部配置一次导出。

#### 下一步衔接 · 建议路径

建议路径：吾与点的CSV／JSON → 核对字段与出处 → 转换DocuXML → DocuSky；类型和多值关系可能在转换中丢失，需抽样核验，未验证自动直连。

把文本和图像中的信息按研究者定义的字段与规则，转成可复核的数据表或知识组织成果。

#### 材料与权限

文本、图片及已有结构化材料；具体任务按模型与字段配置确定。 需要账号；模型、积分与存储条件随服务规则变化。旧版标注功能与新版智能数据平台分开描述。

1. 输入：研究问题与样例

   **定义字段名称、描述、类型以及原文出处字段**

   输出：字段字典
2. 输入：字段与人工样例

   **选择模型，配置规则、提示语和示例**

   输出：可复用的抽取配置
3. 输入：小批文本／图片

   **生成结果并逐行比对原文，修订规则**

   输出：经复核数据与错误记录
4. 输入：复核数据

   **按模块导出数据；配置单独导出并保存**

   输出：数据文件、配置和修订说明

#### 人工检查点

逐条核对同名人物、别称、时间推算、关系方向和否定表述；出处字段须在任务设计时加入。

#### 成果与导出

用户手册说明数据库可导出Excel、CSV、JSON、JSONL；表格字段／规则／示例配置可另导出JSON。不要把数据库导出视为完整图谱、标注与全部项目的无损导出。

#### 下一步衔接 · 建议路径

建议路径：复核后的CSV／JSON → 清洗字段 → DocuXML转换 → DocuSky；节点边表也可另行准备给网络工具。字段和关系映射均需验证。

平行文本 · 对应编辑与分享

### DEDU 对读

由研究者建立多份文本之间的对应关系，组织成可导航、可协作并能分享的对读项目。

#### 材料与权限

来源明确的多个文本及研究者的对应判断；公开项目包括多语言佛典对读，不意味着自动翻译。 一般使用者可申请账号；编辑与分享需按项目权限进行。公开项目可作为阅读样例。

1. 输入：多份文本与版本来源

   **规划篇章和对应单位，保留出处**

   输出：对读结构草案
2. 输入：结构与文本

   **在在线编辑环境组织表格式对应内容**

   输出：平行对读内容
3. 输入：对应内容

   **利用结构导航预览，由成员按权限复核**

   输出：经复核的对读项目
4. 输入：项目成果

   **分享并核查可取得的成果数据**

   输出：阅读链接与经检查的本地备份

#### 人工检查点

对应关系是学术判断；译本缺段、重排及一对多关系须说明依据。自动切分、自动对齐与异文自动识别均未确认。

#### 成果与导出

官方介绍说明成果资料可带走；现行导出格式、对应结构、注释和再导入完整性未实测，不能仅凭公开分享链接视为完成备份。

#### 下一步衔接 · 建议路径

建议路径：校订文本与出处 → 手工组织DEDU对读结构 → 分享。与DocuSky或识典的直接交换未验证；导出时需逐项核对正文、对应关系和注释。

### “对读”要分清的操作

#### 图文对照

文字与书影核对，重点是字图回溯。识典阅读入口属于这一类场景。

#### 版本对勘

比较同书不同底本的异文；字形归一化不能掩盖版本差异。识典整理入口列有文字对勘，自动化细节需核验。

#### 平行文本编辑

组织不同文本或异译的对应关系。DEDU强调对应编辑与分享；多栏展示不等于自动对齐。

#### 文本计算比较

借助语料库与比对工具发现线索。DocuSky相关工具的输入与输出分别检查，计算相似度不能替代文献学判断。
