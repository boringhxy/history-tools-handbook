## 四种通用流程与三组专题案例

单一平台很少覆盖全部环节。原有四种组合与新增三组专题案例强调“入口—整理—分析/发布—保存”的分工关系，可作为项目设计的起点。

<a id="workflow-classics"></a>

01

### 古籍数字整理与学术版本

1. 材料入口：识典古籍 / eScriptorium
2. **整理与建模：**OpenRefine + TEI
3. **分析与发布：**TEI Publisher + Mirador

以底本与版本说明为中心，OCR只是初稿；如另行编码为TEI，应保存源TEI、影像定位和校订记录；识典的具体导出格式及与TEI工具的转换路径须按项目核实。

<a id="workflow-archive"></a>

02

### 档案照片与人物关系研究

1. **材料入口：**Tropy + Transkribus
2. **整理与建模：**OpenRefine + INCEpTION
3. **分析与发布：**Heurist + Gephi + QGIS

从照片级出处进入转录、实体校订、关系/空间建模；网络图和地图结论必须回链原页。

<a id="workflow-oral"></a>

03

### 口述史与音视频档案

1. **材料入口：**ELAN
2. **整理与建模：**受控词表 + 质性编码
3. **分析与发布：**AtoM / Omeka S

知情同意、访问级别和敏感片段处理优先；媒体、EAF、摘要和公开副本分层管理。

<a id="workflow-web"></a>

04

### 网页与 born-digital 史料

1. **材料入口：**Webrecorder
2. **整理与建模：**WARC/WACZ 质检 + 元数据
3. **分析与发布：**Archivematica + AtoM

记录捕获环境与缺失项，保存哈希和采集日志；访问副本、法律限制与长期保存副本分离。

### 三组专题案例工作流

以下是可按步骤开展的示范流程，未宣称完成平台实测。先用少量材料验证权限、字段与交接，再扩大规模。

<a id="case-edition"></a>

案例 01 · 示范流程

### 古籍整理与版本比较

识典古籍 → DEDU 对读

#### 材料与目标

同一作品两种有明确版本说明、允许使用的文本，配少量书影。示范取10个段落，包含缺文或异体字；不将样本当作性能评测。

1. 输入：底本与段落清单

   **在识典查找文本和书影；有整理权限时校订**

   输出：校订文本与版本、卷页记录
2. 输入：经复核的两份文本

   **规划对应单位并在DEDU编辑对应结构**

   输出：可导航的平行文本
3. 输入：对应内容

   **人工标记异文、解释缺段与一对多关系**

   输出：异文记录与判断依据
4. 输入：复核成果

   **按项目权限分享，核查可下载成果**

   输出：公开／受限链接与本地保存清单

#### 人工介入与失败情况

检查异体字、标点、脱衍倒误与文本重排；区分OCR错误、版本异文与编辑改动。佛典异译另按语义、译者和底本系统比较，不能套用逐字校错。自动对齐能力尚未确认。

#### 数据交接 · 未验证直连

识典 → DEDU：传递正文、版本和卷页；可能丢失字图坐标、校订日志。未验证直接导入，必要时手工编辑。

#### 成果清单

校订样例、对应关系、异文表、底本说明和复核记录。

案例 02 · 示范流程

### 近代期刊专题研究

南大平台 → 出处表 → DocuSky

#### 材料与目标

以“教育”相关概念为演示主题，自行限定刊物与年份；实际范围取决于南大平台可访问资源。示范整理20条候选记录，不能据此宣称资源覆盖率。

1. 输入：主题、刊名与年份

   **核对南大平台资源目录与实际可访问范围**

   输出：可检索范围和缺期资料说明
2. 输入：关键词、异称与范围

   **使用实际可用的检索与筛选，记录条件及日期**

   输出：候选文章与检索日志
3. 输入：候选文章

   **核对刊名、卷期、日期、页码及原页依据**

   输出：去重后的文章出处表
4. 输入：有权取得的文本与出处

   **核对导出条件；转换DocuXML后试建库**

   输出：专题语料及检索分析记录

#### 人工介入与失败情况

原页定位、文章级筛选和下载尚待界面验证；资源未收录不等于概念未出现。转载去重和语料规模会影响频率解释。消息、社论、广告、读者来信分别标注；频次、立场与事实判断分别报告。

#### 数据交接 · 未验证直连

南大 → DocuSky：仅传递获准取得的材料，字段映射后转换DocuXML；未验证直接导出／直连。无法取得全文时先做出处表。

#### 成果清单

检索日志、文章清单、卷期页码、排除理由、语料范围说明。

案例 03 · 示范流程

### 人物与事件信息抽取

吾与点 → 人工复核 → DocuSky

#### 材料与目标

来源明确且允许处理的10段短文本。字段设为人物、事件、时间、地点、原文、出处、复核状态；加入同名人物与模糊日期样例。

1. 输入：研究问题与短文本

   **在吾与点定义字段、关系边界和原文出处**

   输出：字段字典及人工示例
2. 输入：字段与示例

   **配置模型、规则和提示语，小批抽取**

   输出：待复核的数据表与配置
3. 输入：抽取结果及原文

   **逐条核对实体、时间和关系，记录修改**

   输出：经复核数据与错误类型
4. 输入：复核数据和配置

   **导出数据与JSON配置；映射DocuXML试建库**

   输出：本地备份、研究库及分析说明

#### 人工介入与失败情况

不把模型补写当作史料陈述；核对同名、否定、关系方向与推算日期。出处缺失的记录不得直接进入证据表。按史料类型增设陈述主体、事件时间、记录时间与亲见／转述／推测，保留互相矛盾的陈述。

#### 数据交接 · 未验证直连

吾与点 → DocuSky：CSV／JSON先做字段、多值和文献单位映射；关系不一定无损转入。未验证自动直连，保留原始导出与配置。

#### 成果清单

复核数据表、字段字典、JSON配置、修改记录及逐条原文出处。
